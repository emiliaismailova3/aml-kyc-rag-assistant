## 2. Мой проект в одной минуте
AI Document Assistant: помощник по AML/KYC документам, который отвечает со ссылками на источники, читает счета и проверяет компании.
- Вопрос → поиск 8 лучших кусков (чанки 700 символов, нахлёст 100, эмбеддинги bge-small, Chroma или pgvector) → LLM отвечает только по найденному, с цитатами [n]; если данных нет, говорит «I don't know based on the available documents».
- Счёт (PDF или скан) → текст или OCR (Tesseract, eng+aze) → LLM возвращает JSON → проверка правилами Pydantic (VÖEN 10 цифр, сумма больше 0, дата не в будущем, строки дают итог ±0,02) → при ошибке до 2 попыток исправления → иначе человеку.
- Сопоставление компании: VÖEN → точное имя → fuzzy ≥0,90 → эмбеддинги ≥0,92 → от 0,75 отправляю человеку.
- Агент с 5 инструментами: база знаний, калькулятор, интернет, SQL только на чтение, извлечение из счёта.
- LLM-клиент: выбор малой или основной модели, повторы с задержкой и случайным разбросом, запасные провайдеры (OpenAI → Anthropic → Groq), лог и /stats, при полном отказе запрос уходит человеку.
- Сбор данных по расписанию: Celery и Redis, robots.txt, лимит по хосту, защита от дублей.
- Новое: голос (Whisper), стриминг ответа, перевод и резюме, MCP-сервер.

## 5. Теория в двух словах
- RAG: сначала найди нужные куски документов, потом дай их модели. Меньше выдумок, есть источники.
- Эмбеддинг: текст как набор чисел, близкий смысл даёт близкие числа. Векторная база ищет ближайшие.
- Чанки: режу документ на куски, чтобы искать точнее. Слишком маленькие теряют смысл, слишком большие размывают поиск.
- Галлюцинация: модель уверенно придумывает. Защита: отвечать только по контексту, цитаты, отказ при нехватке данных.
- Function calling: модель сама решает вызвать функцию и возвращает её имя и аргументы, а выполняет код.
- Агент: цикл «подумал → вызвал инструмент → прочитал результат → ответил». Я ограничила число шагов (10).
- Structured output: модель возвращает JSON по схеме, затем я проверяю его правилами. Модели доверять нельзя, проверять нужно всегда.
- RAGAS: faithfulness (ответ держится на контексте), relevancy (ответ по вопросу), correctness (совпадает с эталоном). Судья это другая LLM, поэтому цифры ориентир.
- Retry с задержкой и разбросом: повторять только временные ошибки (429, 5xx), задержка растёт 1, 2, 4 секунды, разброс не даёт всем клиентам ломиться одновременно.
- Fallback: если провайдер лежит, идём к следующему. Escalation: если лежат все, отдаём запрос человеку.
- Celery и Redis: фоновые задачи; acks_late значит «подтверди после выполнения», чтобы задача не пропала.
- SSE (стриминг): сервер держит соединение и шлёт кусочки. MCP: единый стандарт подключения инструментов к ИИ-приложениям (как USB-C).
- WER: доля неверных слов при распознавании речи. OCR: превращение картинки в текст.
