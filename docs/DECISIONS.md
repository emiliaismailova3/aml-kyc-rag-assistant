# Design decisions

Decisions taken while extending the RAG project into the "AI Document Assistant"
(format: decision, alternatives, why). Newest at the bottom.

## 1. Invoices: text layer first, OCR only as a fallback
- **Decision:** read PDFs with `pdfplumber`; only render pages and run Tesseract when a PDF has fewer than 30 characters of text.
- **Alternatives:** always OCR everything; use a cloud OCR/vision-LLM API.
- **Why:** a text layer is exact and free, OCR is slow and introduces errors. A cloud API would add cost and send documents to a third party.

## 2. Invoices: the LLM returns plain JSON, validated by Pydantic
- **Decision:** ask for one JSON object, parse it, validate with Pydantic; on failure send the error text back (max 2 retries), then `needs_human_review`.
- **Alternatives:** provider "structured output"/JSON-schema mode; LangChain output parsers.
- **Why:** works identically on Groq/OpenAI/Anthropic, no framework, and the repair loop is 20 lines I can explain.

## 3. Fictional reference data is generated by a seeded script
- **Decision:** `scripts/generate_reference_data.py` writes `data/reference/*.json` (50 companies, 40 labeled name pairs); `scripts/generate_synthetic_invoices.py` writes 15 invoices + `labels.json`. Both are committed so tests are reproducible.
- **Alternatives:** hand-written fixtures; real invoices.
- **Why:** real invoices contain personal/business data; generated ones come with exact ground truth for free.
